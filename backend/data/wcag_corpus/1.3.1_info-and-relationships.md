# 1.3.1 Info and Relationships (Level A)

Canonical URL: https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html

Information, structure, and relationships conveyed through presentation can be
programmatically determined or are available in text. Headings, labels,
lists, tables and landmarks must be marked up semantically so assistive
technologies can convey them.

## Why it matters

Visual structure (a bold heading, indentation, a two-column table) communicates
meaning. If that meaning is only visual, screen reader users lose it. Correct
semantics also improves keyboard navigation and search indexing.

## Common failures

- Bold text used instead of real `<h1>`–`<h6>` headings.
- `<div class="list">` with `<div>` items instead of `<ul>`/`<ol>`/`<li>`.
- Tables used for layout, or data tables without `<th scope="...">`.
- Form fields with a visual label placed nearby but no programmatic
  association via `<label for>`, `aria-label`, or `aria-labelledby`.
- Skipped heading levels (h1 → h3) that hide structure from AT.

## Fix guidance

- Use real heading tags in the right order.
- Use `<ul>`/`<ol>` for grouped items.
- For forms, associate every control with a label: `<label for="email">` or
  `aria-labelledby`.
- For data tables, include `<th>` with `scope="col"` or `scope="row"`.
- Use landmark elements: `<header>`, `<nav>`, `<main>`, `<footer>`.
