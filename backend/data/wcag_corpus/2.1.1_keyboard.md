# 2.1.1 Keyboard (Level A)

Canonical URL: https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html

All functionality of the content is operable through a keyboard interface
without requiring specific timings for individual keystrokes.

## Why it matters

Many users — motor-impaired users, screen reader users, power users — rely on
the keyboard. E-commerce flows (add-to-cart, mega menus, variant selectors,
checkout) that only work with a mouse shut these users out.

## Common failures

- `<div onclick>` used as a button with no `role="button"`, no `tabindex`,
  and no keydown handler.
- Custom dropdowns that trap focus or cannot be opened with Enter / Space.
- Mega menus that only open on hover.
- Modals that do not receive focus when opened or do not trap focus.
- Skip links that only activate on click.

## Fix guidance

- Use real `<button>` and `<a>` elements whenever possible.
- If a custom control is unavoidable: add `role="button"`, `tabindex="0"`, and
  handle both Enter and Space keys.
- Ensure every interactive element has a visible focus ring (see 2.4.7).
- Test the entire flow with Tab / Shift+Tab / Enter / Space / Escape.
